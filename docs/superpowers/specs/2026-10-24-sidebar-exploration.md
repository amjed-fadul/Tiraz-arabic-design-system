# Approved sidebar exploration

The user approved the interactive `sidebar-exploration-preview.html` on 24 October and requested implementation locally, without pushing or deploying.

The user's follow-up replaces the fixed map with one naturally scrolling navigation area. Start here and all collection titles scroll together with their links. Each collection expands directly beneath its own title, with one collection open at a time; Illustrations follows AI interfaces in the same flow, rather than being pinned to the bottom. Search stays accessible above the scrolling navigation. Use the existing Tiraz brand, IBM Plex Sans Arabic and Phosphor duotone section icons. Item rows remain text-only. The full section title is one disclosure target. Switching sections opens that collection's gallery and list; clicking the selected title collapses/reopens its list without navigating or moving keyboard focus. Retain the clicked title's relative scroll position where the new content height permits it. Sidebar collapse retains the current page and restores through the same trigger.

Search is always available in the sidebar, across curated components, screens and illustrations, in Arabic and English. Include aliases such as chip/tag/badge and Arabic equivalents, rank exact names first, describe ambiguous results, show a clear empty state and clear action, and support Command/Control K. Search does not navigate or generate pageviews. Escape clears a query before closing the navigation. Selecting a result navigates via a real link and restores the appropriate collection. Use existing route/deep-link contracts and preserve hidden specialist pages under their visible parents.

The generic Library arrival should show Components with the matching sidebar selection; Components and AI interfaces get separate galleries. Keep old category URLs functional. Preserve the current component document, playground, customization and prompt/Copy layouts, and the Night loom landing. Use computed collection counts, with Western digits in sidebar counts for both languages as requested in the latest follow-up. Check light/dark, desktop/mobile, Arabic/English, browser history and focus.

Implementation decisions: retain current `/library?category=…` collection URLs in this local change; a separate URL migration is unnecessary to deliver the approved behavior. Keep search state in Workbench so closing/reopening or switching between the mobile drawer and desktop does not create competing searches. Reuse Input, Button, SiteLink and DocsDrawer. No new dependencies or public component APIs.

The initial fixed-map preview was implemented and then rejected by the user in follow-up. The current direction is the flowing accordion described above. During a search, results appear first within that same scroll area and collection titles follow them; choosing a title clears the query and opens that collection.

A subsequent refinement removes the duplicate small category label and “View all” row from expanded collections. Links start directly beneath their main section title. Search retains its own results label and count, and collection regions retain accessible names.
