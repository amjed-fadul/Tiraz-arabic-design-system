## Review Focus

1. **No key or focus move decides something unread.**
   - Opening an inbox row, a request arriving, a step turning needs-you and a row leaving its tab never put focus on Approve.
   - Escape anywhere in an open inbox row folds it and records nothing.
   - Quick decisions exist only for reversible requests, and a late resolve on a request that expired or changed records nothing.

   → Task 4: `opens a row without moving focus, and offers no approve-all`, `decides inline only for reversible requests…`, `folds an open row on Escape, anywhere in it, and records nothing`. Task 2: `keeps focus off Approve when a step turns needs-you`.
2. **Undo never claims a recall.** An Undo after the window, an Undo the host can't honor and a second Send never produce a recall or a second send.
   → Task 5: `offers Undo only inside the host's window and never claims a recall`, `sends what it shows, once…`.
3. **An irreversible permission stays «اسأل دائمًا» whatever level the host passes.** → Task 6: `locks irreversible actions…`.
4. **A row that leaves its tab never drops focus to the page.** → Task 4: `keeps a resolved row for its receipt, then moves it, keeping focus`.
5. **Counts agree and regions speak once.** This covers طلب and مهمة at every plural boundary, the dual verb («مهمتان تعملان») and Western digits. The inbox speaks only when its counts change, the meter only when its status word changes, and each note once.
   → Task 4: `counts with Arabic agreement and speaks only when counts change`. Task 6: `…announces each crossing once`. Task 2: `announces each note once`.

## Decisions made in this plan

Each fills a gap the spec or research leaves, and each is cheap to reverse.

1. **Ask your data takes a chart family whole.** `chart` is `{ type, props }` with that family's own props, `CartesianChartProps` or `DonutChartProps`. The type control only calls `onChartTypeChange`, and the host reshapes its data for the type it offers. §13.1 says "within the families that fit the data", and the host owns the data.
2. **Ask your data has §13.1's four states only**, with no Stop and no writing state. Its method is strings, `{ range: string; filters?: string }`, with `sources` as the tables, so a copy can carry it.
3. **The inbox's API.** §13.2 gives none, and Research §4 sketches only part of one.
   - A `DecisionInboxItem` is an approval (`request`), a set of questions, a draft or a task, in one of four statuses.
   - Rows keep the host's order, since the host knows what is urgent.
   - «بانتظارك» is the default tab.
   - `tab`, `agent` and `expanded` are controllable; `expanded` lets the page hold an open row.
4. **Quick decisions have no shortcut, are secondary, and show only while their row is closed.**
   - A row can't open while its quick decision is in flight. An accepted one reaches the opened card through `value`.
   - Why: a chord's target is unclear in a list of moving rows, §9 allows one primary button, and one decision path at a time keeps duplicates out.
5. **Escape anywhere in an open inbox row folds it, returns focus to its title and records nothing**, as Plan 4's Decision 27 does for dialogs. This overrides §8's Escape-rejects inside the inbox only.
   - Why: in an open row the first Tab stop is the card's Reject, so an Escape meant to fold would reject. Inside the Dashboard's Sheet, Radix takes Escape anyway, so one rule keeps the inbox the same everywhere.
   - How: the row catches Escape in `onKeyDownCapture` and calls `preventDefault()`, which `useShortcuts` already skips. An internal context tells DecisionBar to drop the card's Esc hint inside the inbox.
6. **The 5 s receipt starts when the host moves an item out of the shown tab.** `receiptFor` sets it: 5 by default, 0 for none. The host owns the status, and §5 lets hosts turn UI timers off.
7. **The counts follow the agent filter.** Every waiting row counts as a طلب, failed tasks included, and every running row as a مهمة. That is Research §4 item 5's sentence.
8. **Question rows keep their draft answers inside the inbox** and send them through `onAnswer(id, answers, { signal })`. AskUserQuestions is controlled, and a host shouldn't hold one draft per row.
9. **The undo countdown never pauses, and Undo claims nothing.**
   - The countdown shows the host's window, which a hover can't stretch. A pause would show undo time the host isn't giving, or hold the message while the pointer rests where Send was. This departs from §11 and §18's pause rule, which serves auto-start.
   - Only the host's next status speaks: back to ready means sending was cancelled; sent means it went before it could be cancelled.
   - The window is a time limit on Undo, so WCAG 2.2.1 applies: the host takes it from a setting the person controls before meeting it, either off or adjustable to at least ten times the default. The real-time exception doesn't cover a hold the host chose, and a 20 s extension warning can't fit in a 10 s window.
   - `undoWindow` is the seconds left in the host's hold when the countdown mounts, so a remount never offers Undo after the hold ends.
10. **Send hands the host the text on screen**: `onSend(text)`, with `diffText` while a suggestion shows, once per ready status.
    - Send keeps ⌘↵, as §8 and §13.3 say.
    - Discard is «تجاهل», Suggested edits' word, and the discarded state is the stopped pill reading «تم التجاهل».
11. **Assistant controls is the person's settings, not AI output.** It has no AI mark (Woven §14), no pill and no state switcher. A locked row shows «اسأل دائمًا» whatever `level` the host passes.
12. **ContextMeter gains `inline` for §13.4's "detail view"**; today it is a popover only.
    - `announcement` defaults to polite, as ThinkingPanel's and Countdown's do.
    - Inside Assistant controls, the meter's region is the pattern's one region.
13. **ApprovalCard gains `agent`**, so a handed-off step's request names who asks (Research §7 item 1).
14. **The Dashboard tells its own story**, its customers and orders in AED, not the finance story. Its inbox opens in a Sheet, and approving its reversible request reactivates the customer in memory.
15. **The Wave 2 page states** (Docs §8 leaves them to the build):
    - Ask your data: Thinking · Done★ · Failed · Empty, with Replay;
    - Decision inbox: Waiting★ · Expanded · Empty;
    - Draft for review: Writing · For review★ · Sending · Sent · Discarded, with Replay;
    - Assistant controls: no switcher.
16. **Evidence lives in `docs/woven/after-wave-2/`**, a new folder, so nothing tracked is overwritten.

  - the body as written, then a blank line;
  - «المصادر» / "Sources", then one line per source: `{number}. {title}`, plus ` — {href}` when `sourceHref` accepts it, with numbers in the reader's digits;
  - with `method`, its title and lines go between the body and the sources, after a blank line;
  - with no sources, there is no sources block.
- **«+N» (§2 item 1).**
  - Past three chips, a button shows «+٤» and carries `aria-expanded`. Its name starts with what it shows (WCAG 2.5.3, Label in Name): the visible «+٤», then `showAll` as hidden text, so it reads «+٤ عرض كل المصادر» / "+4 Show all sources".
  - It reveals the rest, then reads `showFewer` («عرض أقل» / "Show fewer"). The revealed chips don't animate in, and focus stays on the button.
- **Example:** `onCopy={(text) => navigator.clipboard.writeText(text)}`.
